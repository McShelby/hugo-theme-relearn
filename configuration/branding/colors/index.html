Colors

The Relearn theme offers color variants to change your site’s appearance. Each color variant consists of a CSS file and optional settings in your project configuration.

You can use the shipped variants, customize them, decorate them with effects, or create your own. The interactive variant generator can help you with this.

Once set up in your project configuration, you can switch variants using the selector at the bottom of the menu.

Shipped Variants

The theme ships with the following set of variants

Family Variants Notes
Relearn Light, Dark The classic Relearn default, coming with signature green, a dark sidebar and a light or dark content area
Zen Light, Dark A more relaxed white/grey look, coming with blue accents and a light or dark sidebar and content area
Contrast Light, Dark High contrast, coming with black text on white or white text on black
Book Light, Dark A book-like look with calligraphic titles, coming with burgundy accents on warm paper tones or garnet accents on dark leather tones
Tome Light, Dark Book with a glow around the page
Unicorn Light, Dark A gradient across sidebar and topbar, pastel with magenta accents in Light and vivid in Dark
Glow Powder, Neon Unicorn Light with a glow around the page, Unicorn Dark with glowing text
Retro Learn, Blue, Green, Red The default of the old Learn theme, coming with signature light purple, and variations tinted in blue, green or red

Changing the Variant

Option Set the themeVariant option to the list of your site’s variants. Each entry is a table with the identifier of the variant and further parameters.

The identifier names the variant’s file assets/css/theme-<IDENTIFIER>.css, taken from your site or else from the theme.

hugo.
params:
  themeVariant:
  - identifier: relearn-light
  - identifier: relearn-dark
[params]
  [[params.themeVariant]]
    identifier = 'relearn-light'

  [[params.themeVariant]]
    identifier = 'relearn-dark'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "relearn-light"
         },
         {
            "identifier": "relearn-dark"
         }
      ]
   }
}

An entry with nothing but its identifier can be written as the identifier alone.

hugo.
params:
  themeVariant:
  - relearn-light
  - relearn-dark
[params]
  themeVariant = ['relearn-light', 'relearn-dark']
{
   "params": {
      "themeVariant": [
         "relearn-light",
         "relearn-dark"
      ]
   }
}

With more than one variant, the variant switcher is shown at the bottom of the menu and the first variant is the default. To change the position or the icon of the variant switcher, see the chapter on sidebar configuration.

A site with only one variant can set themeVariant to that variant instead of a list. The variant switcher is not shown then.

hugo.
params:
  themeVariant: relearn-light
[params]
  themeVariant = 'relearn-light'
{
   "params": {
      "themeVariant": "relearn-light"
   }
}

Default is auto. So without themeVariant, your site adjusts to the OS settings with relearn-light for light and relearn-dark for dark mode.

Force the Default Variant

Option Set forceDefaultThemeVariant to true to keep the reader’s selection in the browser’s session storage instead of its local storage, so every new visit starts with the first variant of themeVariant again, even if the reader selected another one before. Default is false.

hugo.
params:
  forceDefaultThemeVariant: true
  themeVariant:
  - relearn-light
  - relearn-dark
[params]
  forceDefaultThemeVariant = true
  themeVariant = ['relearn-light', 'relearn-dark']
{
   "params": {
      "forceDefaultThemeVariant": true,
      "themeVariant": [
         "relearn-light",
         "relearn-dark"
      ]
   }
}

If your site is opened from the file system, this option has no effect.

Adjust to OS Settings

A variant with the auto parameter matches the OS light/dark setting. The first entry of auto is the variant for light mode, the second the one for dark mode. Usually it makes sense to set it in the first position and make it the default. A site can have several of them.

hugo.
params:
  themeVariant:
  - auto:
    - zen-light
    - zen-dark
    identifier: zen-auto
  - identifier: red
[params]
  [[params.themeVariant]]
    auto = ['zen-light', 'zen-dark']
    identifier = 'zen-auto'

  [[params.themeVariant]]
    identifier = 'red'
{
   "params": {
      "themeVariant": [
         {
            "auto": [
               "zen-light",
               "zen-dark"
            ],
            "identifier": "zen-auto"
         },
         {
            "identifier": "red"
         }
      ]
   }
}

Option A missing entry of auto is taken from the themeVariantAuto option, or else from the first two variants of themeVariant that are neither auto mode nor scripted, or else it is relearn-light for light and relearn-dark for dark mode. The identifier auto makes a variant an auto mode variant even without the auto parameter.

hugo.
params:
  themeVariant:
  - auto
  - red
  themeVariantAuto:
  - learn
  - neon
[params]
  themeVariant = ['auto', 'red']
  themeVariantAuto = ['learn', 'neon']
{
   "params": {
      "themeVariant": [
         "auto",
         "red"
      ],
      "themeVariantAuto": [
         "learn",
         "neon"
      ]
   }
}

Parameters

Name Default Notes
identifier <empty> Must correspond to the name of a color variant either in your site’s or the theme’s directory in the form assets/css/theme-<IDENTIFIER>.css.
name see notes The name to be displayed in the variant selector. If not set, the identifier is used in a human readable form.
auto <empty> If set, the variant is an auto mode variant. The first entry is the color variant for light mode, the second for dark mode.
script <empty> If set, the variant is chosen by a script of this name and needs no stylesheet of its own. It can’t be combined with auto or print.
params <empty> Values of the site’s params that are overridden while this variant is active, see below. A scripted variant passes them to its script instead.
hidden false If true, the variant will not be shown in the variant switcher but is still available for internal use (e.g. to override parameter when used as a sub-variant of an auto mode variant, or to be chosen by a script).
print see notes The print variant used instead of this variant when printing. If not set, the one of the themeVariantPrint option is used. An auto mode variant ignores it and prints with the print variants of its light and dark variant.

Variant Parameters

Some of the site’s params can be given a different value for a variant by setting it in the variant’s params. While the variant is active, it takes the place of the site’s value.

Name Notes
logo Logo of the variant, only its src
hugo.
params:
  themeVariant:
  - identifier: relearn-light
  - identifier: neon
    params:
      logo:
        src: /images/logo-neon.svg
[params]
  [[params.themeVariant]]
    identifier = 'relearn-light'

  [[params.themeVariant]]
    identifier = 'neon'

    [params.themeVariant.params]
      [params.themeVariant.params.logo]
        src = '/images/logo-neon.svg'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "relearn-light"
         },
         {
            "identifier": "neon",
            "params": {
               "logo": {
                  "src": "/images/logo-neon.svg"
               }
            }
         }
      ]
   }
}

Dividers

To group the entries of the variant switcher, put an entry { type = 'divider' } between them. It draws a line in the variant switcher and is no variant itself.

Give the divider a name to label the group following it, like { type = 'divider', name = 'Classic' }. A named divider may also stand first to label the first group.

Of consecutive dividers only the last one is kept. Trailing dividers are dropped, as are leading ones without a name.

Scripted Variants

A variant with a script lets a script choose the variant to show, for example by the current date or the time of day. The reader selects it in the variant switcher like any other variant, while the page shows and prints the variant the script chooses. The script is asked on every page load.

The script is the file assets/js/<SCRIPT>.js of your site or the theme. It must define a function of the same name. The function is called with the configuration of all variants and the configuration of the variant asked for, and returns the identifier of a variant without a script. Each configuration holds every option of its variant as the theme prepared it from yours, so a script may read options of its own from the params of its variant. A script must not change them. It may choose hidden variants and scripted variants, whose script is asked in turn, so a script choosing by the season can leave the time of day to another.

​
function myVariantByWeekday(variants, variant) {
  var weekday = new Date().getDay();
  return weekday == 0 || weekday == 6 ? 'zen-light' : 'relearn-light';
}
hugo.
params:
  themeVariant:
  - identifier: my-weekday
    name: Weekday/Weekend
    script: myVariantByWeekday
  - hidden: true
    identifier: relearn-light
  - hidden: true
    identifier: zen-light
[params]
  [[params.themeVariant]]
    identifier = 'my-weekday'
    name = 'Weekday/Weekend'
    script = 'myVariantByWeekday'

  [[params.themeVariant]]
    hidden = true
    identifier = 'relearn-light'

  [[params.themeVariant]]
    hidden = true
    identifier = 'zen-light'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "my-weekday",
            "name": "Weekday/Weekend",
            "script": "myVariantByWeekday"
         },
         {
            "hidden": true,
            "identifier": "relearn-light"
         },
         {
            "hidden": true,
            "identifier": "zen-light"
         }
      ]
   }
}

If the function fails, returns something else or a scripted variant that was already asked for, the first variant of the variant switcher that isn’t scripted is shown instead. If the variant switcher has none, it is the first variant of themeVariant that isn’t scripted, even if it is hidden. If all variants of themeVariant are scripted, the build stops with an error.

Variant by Time

The theme ships with the script themeVariantByTime, which chooses a variant by the local time of the reader.

The themeVariantByTimeMappings in the params of its variant map the local time a variant starts, like 07:30, to the identifier of the variant to show from then on. Before the earliest time of the day, the variant of the latest time is shown.

hugo.
params:
  themeVariant:
  - identifier: my-time
    name: Morning/Day/Night
    params:
      themeVariantByTimeMappings:
        '06:00': relearn-light
        '09:00': zen-light
        '20:00': zen-dark
    script: themeVariantByTime
  - hidden: true
    identifier: relearn-light
  - hidden: true
    identifier: zen-light
  - hidden: true
    identifier: zen-dark
[params]
  [[params.themeVariant]]
    identifier = 'my-time'
    name = 'Morning/Day/Night'
    script = 'themeVariantByTime'

    [params.themeVariant.params]
      [params.themeVariant.params.themeVariantByTimeMappings]
        '06:00' = 'relearn-light'
        '09:00' = 'zen-light'
        '20:00' = 'zen-dark'

  [[params.themeVariant]]
    hidden = true
    identifier = 'relearn-light'

  [[params.themeVariant]]
    hidden = true
    identifier = 'zen-light'

  [[params.themeVariant]]
    hidden = true
    identifier = 'zen-dark'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "my-time",
            "name": "Morning/Day/Night",
            "params": {
               "themeVariantByTimeMappings": {
                  "06:00": "relearn-light",
                  "09:00": "zen-light",
                  "20:00": "zen-dark"
               }
            },
            "script": "themeVariantByTime"
         },
         {
            "hidden": true,
            "identifier": "relearn-light"
         },
         {
            "hidden": true,
            "identifier": "zen-light"
         },
         {
            "hidden": true,
            "identifier": "zen-dark"
         }
      ]
   }
}

Variant by Occasion

The theme ships with the script themeVariantByOccasion, which chooses a variant by the festivals and seasons of the current date.

The themeVariantByOccasionMappings in the params of its variant list which variant to show for which occasion. The entries are checked in the configured order and the first match wins, so put the more specific ones first. An entry may also show a variant of the script by time, so the occasion picks the variant and the time of day picks between its light and dark version.

Name Notes
occasion The ID of an occasion, a date like 2026-12-24 or a date of every year like 12-24, which match on the local date of the reader. A list of two of them matches from the start of the first to the end of the second, like [ 'advent', 'epiphany' ] or [ '11-15', 'new-year' ]. Without it, the entry always matches, which makes it a good last entry.
variant The identifier of the variant to show.

A festival has an ID like christmas or lunar-new-year and a season one like season-winter-north-meteorological, see the available occasions.

hugo.
params:
  themeVariant:
  - identifier: my-occasion
    name: By Occasion
    params:
      themeVariantByOccasionMappings:
      - occasion:
        - advent
        - epiphany
        variant: my-christmas
      - occasion: season-winter-north-meteorological
        variant: my-winter
      - variant: relearn-auto
    script: themeVariantByOccasion
  - auto: []
    identifier: relearn-auto
  - hidden: true
    identifier: my-christmas
  - hidden: true
    identifier: my-winter
[params]
  [[params.themeVariant]]
    identifier = 'my-occasion'
    name = 'By Occasion'
    script = 'themeVariantByOccasion'

    [params.themeVariant.params]
      [[params.themeVariant.params.themeVariantByOccasionMappings]]
        occasion = ['advent', 'epiphany']
        variant = 'my-christmas'

      [[params.themeVariant.params.themeVariantByOccasionMappings]]
        occasion = 'season-winter-north-meteorological'
        variant = 'my-winter'

      [[params.themeVariant.params.themeVariantByOccasionMappings]]
        variant = 'relearn-auto'

  [[params.themeVariant]]
    auto = []
    identifier = 'relearn-auto'

  [[params.themeVariant]]
    hidden = true
    identifier = 'my-christmas'

  [[params.themeVariant]]
    hidden = true
    identifier = 'my-winter'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "my-occasion",
            "name": "By Occasion",
            "params": {
               "themeVariantByOccasionMappings": [
                  {
                     "occasion": [
                        "advent",
                        "epiphany"
                     ],
                     "variant": "my-christmas"
                  },
                  {
                     "occasion": "season-winter-north-meteorological",
                     "variant": "my-winter"
                  },
                  {
                     "variant": "relearn-auto"
                  }
               ]
            },
            "script": "themeVariantByOccasion"
         },
         {
            "auto": [],
            "identifier": "relearn-auto"
         },
         {
            "hidden": true,
            "identifier": "my-christmas"
         },
         {
            "hidden": true,
            "identifier": "my-winter"
         }
      ]
   }
}

Random Variant

The theme ships with the script themeVariantByRandom, which chooses one of the variants of themeVariant without a script by chance, including hidden ones. As every script, it is asked on every page load, so each page may show another variant.

hugo.
params:
  themeVariant:
  - identifier: relearn-light
  - identifier: zen-light
  - identifier: my-random
    name: Random
    script: themeVariantByRandom
[params]
  [[params.themeVariant]]
    identifier = 'relearn-light'

  [[params.themeVariant]]
    identifier = 'zen-light'

  [[params.themeVariant]]
    identifier = 'my-random'
    name = 'Random'
    script = 'themeVariantByRandom'
{
   "params": {
      "themeVariant": [
         {
            "identifier": "relearn-light"
         },
         {
            "identifier": "zen-light"
         },
         {
            "identifier": "my-random",
            "name": "Random",
            "script": "themeVariantByRandom"
         }
      ]
   }
}

Print Variant

When a page is printed or shown as its print version, it doesn’t use the variant selected by the reader but its print variant, with the theme’s print variables on top.

The print variables set every color that depends on a light or dark background to values made for paper, with links, titles, code, boxes and the topbar in black on white. So the print shows the fonts of the print variant but the colors of paper. The print variables are in the theme’s assets/css/format-print-variables.css. To change them for your site, copy the file into your site’s assets/css directory and edit it. To keep a single value of a print variant on paper, mark it !important in the variant.

​
:root {
  --MAIN-LINK-color: rgba( 0, 0, 255, 1 ) !important; /* blue links also on paper */
}

Option Set themeVariantPrint to the print variant of your site. Default is relearn-light.

hugo.
params:
  themeVariantPrint: zen-light
[params]
  themeVariantPrint = 'zen-light'
{
   "params": {
      "themeVariantPrint": "zen-light"
   }
}

Each variant can name its own print variant with the print parameter, which wins over themeVariantPrint. A variant naming itself prints with its own fonts.

If a print variant has a different print variant itself, by its print parameter or by themeVariantPrint, that one is used instead, and so on, until a variant names itself. If this comes back to a variant already visited, the build stops with an error. An auto mode variant prints with the print variants of its light and dark variant, following the reader’s OS setting.

In the following example, both variants print with the fonts of the light variant.

hugo.
params:
  themeVariant:
  - auto:
    - my-light
    - my-dark
    identifier: my-auto
  - identifier: my-light
    print: my-light
  - identifier: my-dark
    print: my-light
[params]
  [[params.themeVariant]]
    auto = ['my-light', 'my-dark']
    identifier = 'my-auto'

  [[params.themeVariant]]
    identifier = 'my-light'
    print = 'my-light'

  [[params.themeVariant]]
    identifier = 'my-dark'
    print = 'my-light'
{
   "params": {
      "themeVariant": [
         {
            "auto": [
               "my-light",
               "my-dark"
            ],
            "identifier": "my-auto"
         },
         {
            "identifier": "my-light",
            "print": "my-light"
         },
         {
            "identifier": "my-dark",
            "print": "my-light"
         }
      ]
   }
}

A print variant doesn’t need to be part of themeVariant. If you list it, set it hidden to keep it out of the variant switcher.

The style rules of a print variant apply to the print as well. Wrap rules meant for the screen only as shown for screen-only rules.

Creating Variants

Modifying Variants

In case you like a shipped variant but only want to tweak some aspects, you have two choices. Don’t edit the file in the theme’s directory! You will lose the ability to later easily upgrade your theme to a newer version.

  1. Copy and change

    You can copy the shipped variant file from the theme’s themes/hugo-theme-relearn/assets/css directory to the site’s assets/css directory and either store it with the same name or give it a new name. Edit the settings and save the new file. Afterwards, you can use it in your project configuration by the chosen name.

  2. Create and import

    You can create a new variant file in the site’s assets/css directory and give it a new name. Import the shipped variant, add the settings you want to change and save the new file. Afterwards, you can use it in your project configuration by the chosen name.

    For example, you want to use the relearn-light variant but want to change the syntax highlighting schema to the one used in the neon variant. For that, create a new assets/css/theme-my-branding.css in your site’s directory and add the following lines:

    ​
    @import "theme-relearn-light.css";

:root {
  --CODE-theme: neon; /* name of the chroma stylesheet file */
  --CODE-BLOCK-color: rgba(226, 228, 229, 1); /* fallback color for code text */
  --CODE-BLOCK-BG-color: rgba(40, 42, 54, 1); /* fallback color for code background */
}

    Afterwards, put this in your project configuration to use your new variant:

    hugo.
    params:
  themeVariant: my-branding
    [params]
  themeVariant = 'my-branding'
    {
   "params": {
      "themeVariant": "my-branding"
   }
}

    In comparison to copy and change, this has the advantage that you profit from any adjustments to the relearn-light variant while keeping your modifications.

Effects

Effects decorate a variant beyond its colors. They are shown on screen only and don’t apply to print.

The theme ships with the following effects

Name Notes
text-glowing Makes titles, menu entries and boxes glow. Set --TEXT-GLOWING-color for the color of the glow, default is the text color. Made for dark variants.
page-glowing Lets a glow shine in from the edges of the screen. Set --PAGE-GLOWING-color for the color of the glow, default is the primary color.
season-winter Decorates the page with a winter scene of snow, trees, lights and a lantern.
backdrop-faded Fades the scene behind the content towards the background color, to keep the content readable on top of a scene. Set --BACKDROP-FADED-color for the color, default is the background color of the content.
backdrop-milky Lays milky glass over the scene behind the content, blurring it and fading it towards the background color. Set --BACKDROP-MILKY-color for the color, default is the background color of the content.

To use an effect, create your own variant that imports a variant and the effects you want, one after the other. Effects sharing the first part of their name, like backdrop-faded and backdrop-milky, can’t be combined; choose one of them.

​
@import "theme-zen-dark.css";
@import "effect-season-winter.css";
@import "effect-backdrop-faded.css";

Afterwards, put this in your project configuration to use your new variant:

hugo.
params:
  themeVariant: my-winter
[params]
  themeVariant = 'my-winter'
{
   "params": {
      "themeVariant": "my-winter"
   }
}

See the effects in action with Powder or Winter Tome Dark of this documentation.

You can write your own effect as assets/css/effect-<NAME>.css. An effect can’t import other files. Files it refers to with url() must be placed in your assets directory and given relative to the effect, like url('../images/my-effect/snow.svg'). Wrap its rules as shown for screen-only rules.

Screen-only Rules

The style rules of a variant also apply when it is used as a print variant. If your variant contains style rules that are meant for the screen only, wrap them as follows. The print version of a page is shown on screen too, so @media screen alone is not enough.

​
:root:not([data-r-output-format='print']) {
  @media screen {
    h1 {
      text-shadow: 0 0 4px rgba( 255, 255, 255, 1 ); /* a glow, only for the screen */
    }
  }
}

Non-standard Modifications

You may feel tempted to add further modifications besides just setting CSS variables in your custom variant stylesheet.

While this is possible, please note that due to the way the theme uses the variant files, the following will not work:

  • @font-face rules - they need to be moved to assets/css/fonts.css, assets/css/custom.css or layouts/partials/custom-header.html
  • rules selecting the html element - replace html with :root

Advanced Topics

Variant-specific Logos

You can override the default logo of a site for each variant.

Linking to a Variant

You can select a variant by adding the query parameter variant, containing the identifier of the variant, to the URL of any page of your site, e.g. https://example.com/my-page?variant=relearn-dark. This also works for links in your content.

This has the same effect as if the reader had selected the variant with the variant switcher: The selection is stored in the reader’s browser, replacing a previous one, and carried over to the following presented pages. The query parameter is removed from the URL in the browser’s address bar afterwards.

The variant must be one of your configured variants and must not be hidden. Otherwise the query parameter is ignored.

React to Variant Switches in JavaScript

Once a color variant is fully loaded, either initially or by switching the color variant manually with the variant selector, the custom event themeVariantLoaded on the document will be dispatched. You can add an event listener and react to changes.

​
document.addEventListener( 'themeVariantLoaded', function( e ){
  console.log( e.detail.variant ); // `relearn-light`
});
